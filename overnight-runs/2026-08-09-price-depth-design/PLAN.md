## 目的と現状

検索画面の予算フィルタは「選択した用途に一致する確認済みの1日施設基本料」を対象とするが、
料金観測があるのは **1,178候補中216施設（18%）** に留まる（2026-08-09時点、観測2,881件）。
未観測962施設のうち、多くの県で23施設前後が未観測であり、県単位の予算比較がまだ機能しない。

目標: **各都道府県で、体育館型（アマチュアスポーツ用途）と舞台型（舞台公演用途）の
「確認済み1日基本料」を持つ施設を最低5件ずつ**にする（全国目標: 追加観測 約500〜700件）。

## 優先順位

1. 過去大会台帳（JJF・JYYF・WYYC・AJDC・OIDC・KWC）と結びつく候補で料金未観測のもの
2. 県内の料金観測ゼロ地帯（埼玉・長崎・岩手・秋田・宮崎・岐阜・和歌山・徳島など各23施設が未観測）
3. 区画・運用は構造化済みだが料金だけ無い施設（追加調査が1ページで済むことが多い）

## 収録規律（過去waveと同一。緩めない）

- **公式料金表・条例・指定管理者ページのみ**を出典とし、URL・観測日を必ず記録する
- 時間帯・平日休日・入場料の有無・営利非営利・市内外・税・適用日を**列で保持**する
- 条件で変動し1日額に正規化できない料金は**収録しない**（曖昧な日額を作らない）
- 冷暖房・設備・警備等の付帯費は基本料から分離。不明値は空欄または`unknown`（0円にしない）
- 新規URLは `data/url-audit.csv` の監査対象に含める

## 1 waveの単位と検証

- 1 wave = 1都道府県（または5施設程度）
- 各wave後: `npm run audit` → `npm --prefix web run data:generate` → `npm run validate` →
  対象ファイルのみコミット（data/price-observations.csv、必要なら venue-details.csv・venue-operations.csv）
- 公開デプロイは毎waveではなく**ラン終了時に1回**（Sitesデプロイは認証を持つCodex CLIに委譲。
  手順は 2026-08-09 のバージョン205〜207 デプロイと同じ: sites remoteへfast-forward push →
  web/dist再生成 → アーカイブをデプロイ → 両公開URLの検証 → web/dist復元）

## 実行体制（承認時に確定させる項目）

- 実行者: Claude単独（サブエージェントなし）を既定とする。並列化する場合は
  人数・モデル・範囲を本人に事前提示して包括許可を得る
- モデル: 収集・整形はSonnet級で可。収録可否の判断（正規化できるか）は規律が明文化されているため
  Sonnetでも可だが、迷った場合は「収録しない」に倒す
- 終了条件: 目標達成、またはトークン・時間予算の残りが最終検証分を下回った時点
- Reserve Queue（早期完了時のみ）: URL監査で検出済みの client_error 81件の出典URL修繕
  （新URLの再探索と差し替え。削除はしない）

## 承認時に本人へ確認する点

1. 目標値（県ごとに体育館型5件・舞台型5件）はこの水準でよいか
2. 夜間の包括許可の範囲（単独/並列、モデル、予算、終了時刻）
3. デプロイをラン終了時1回とする運用でよいか
