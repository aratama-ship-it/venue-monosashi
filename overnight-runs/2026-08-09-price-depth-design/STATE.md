## 進捗の見方（2026-08-09 追加）

**`npm run price-coverage` が唯一の進捗指標。** wave対象はこの表を見てから選ぶ。

- 出力: 都道府県 × 施設タイプ（舞台型/体育館型）ごとの「確認済み1日施設基本料を持つ施設数 / その型の候補数（不足数）」
- 施設タイプの判定は **検索画面 `web/app/venue-search.tsx` の `rolesForVenue` と同じロジック**
  （facility_pattern だけでなく space_type・stage_type も見る）。検索画面が舞台/スポーツとして
  扱う施設を分母にそろえるため
- 「確認済み1日基本料」= 次のいずれか。**検索画面の予算フィルタが拾う2系統と同じ**
  （`venue-search.tsx` の officialDaily / derivedDaily。UIは「公式日額」「区分合計の参考額」と出し分ける）
  1. **公式日額**: price-observations の `charge_category=facility` かつ `unit=per_day` かつ
     use_caseがsetup/準備/撤去でない かつ `verification_status=verified`
  2. **参考合計**: budget-scenarios の `verification_status=derived_from_verified_components`
     （公式の時間帯区分が無条件で1日を覆う場合だけ合算。component は `unit=per_slot` の verified 行に限る）
- `--prefecture=岩手県` で県内の施設別内訳（PRICED / no-price）を一覧表示
- `--write` で `data/prefecture-price-coverage.csv` を更新
- **「候補25件中◯件が料金未観測」という数え方は使わない。** 施設タイプを区別せず、目標に対する
  進捗が読めないため（Wave2着手時にこの粗い数え方で埼玉の体育館型を誤判定した）

## 注意

- WebFetchの要約を鵜呑みにせず、金額が計算に合うか（午前+午後+夜間≒全日など）確認してから収録する。
  Wave3では要約が「1時間あたり11,120円」と返した表の解釈が確定できず、その施設は収録を見送った
- **料金表がPDFや画像で機械可読でないとき**: `pypdf` でテキスト抽出 →崩れる場合は
  `mkdir -p /tmp/qlout && qlmanage -t -s 2400 -o /tmp/qlout file.pdf` でPNG化してから目視で読む
  （このMacには pdftotext / poppler が入っていない）
- **自治体サイトは料金改定の直後に注意。** 掲載表が改定前か後かを、改定告知ページと突合して確認する
  （Wave3の長崎市平和会館は2026-04-01改定後の額であることを告知と照合して確定した）
- ローカル動作確認は `npm --prefix web run start`（本番ビルド）を使う。
  **`npm --prefix web run dev` は生成データが大きく "Maximum call stack size exceeded" で500になる**
  （2026-08-09時点。データ量由来でアプリの不具合ではないが、dev では確認できない）
- 公開デプロイは日次ラン終了時に1回（Codex委譲、バージョン検証つき）
