## 収録品質の段階

### Candidate minimum

- 現行の自治体、施設、指定管理者いずれかの公式URLがある。
- 施設名、都府県、市区町村、現在の貸出施設としての実在を確認できる。
- 閉館、長期休館、利用者限定、改称・運営者変更を区別して記録する。
- 既存候補の正規化施設名、住所、公式URLとの重複を確認する。

### Searchable minimum

- 少なくとも1つの実在する貸出区画を `venue-details.csv` に持つ。
- 面積、定員、天井高、舞台、競技利用等は公式明示値だけを入れ、未確認値を推定しない。

### Practical depth

- 直接公表された料金を最低1区分登録する。または、料金が問合せのみであることを明記する。
- 予約開始、締切、準備撤収、搬入、飲食・物販、通信のうち確認できる運用条件を登録する。

## 100施設時点の品質目標

- 公式URL・市区町村・重複確認: 100%
- 少なくとも1区画の詳細あり: 80%以上
- 直接料金あり: 40%以上
- 運用条件あり: 30%以上
- 閉館・施設違い・異区画合算・推定日額の既知エラー: 0

## 統合順序

1. 発見台帳で施設名、自治体、公式URL、閉館状態を確認する。
2. 既存正本と正規化名称・公式URL・住所で重複監査する。
3. 候補IDと詳細IDを最終ベースラインから一括採番する。
4. 料金・運用を異区画・用途・曜日・入場料条件ごとに分離する。
5. `npm run audit`、カバレッジ監査、生成物テストを通す。
6. 公開は別の明示承認とし、ローカル統合・ビルド・公開確認を混同しない。
